Autosize Textarea Visibility Guard

Status: Implemented (v2.4.2)

Overview

This proposal introduces a stabilization improvement to the autosizing textarea implementation used in the Base textbox component. The change prevents incorrect height calculations when the textarea is measured while it is not visible in the layout tree.

The issue commonly occurs when the component remains mounted but is hidden via display: none, which is typical for tab panels implemented using Vue's v-show.

When autosize logic runs in this state, scrollHeight returns 0, causing the component to write an invalid inline height of 0px. This results in collapsed textareas when the element becomes visible again.

The proposed change adds a visibility guard to the autosize routine to prevent measurement when the element is not participating in layout.

This change is fully backward compatible and is categorized as a patch-level stabilization.

Problem Description

The autosize algorithm currently performs the following steps:

1. Reset height to auto.
2. Measure scrollHeight.
3. Apply the measured height.

Simplified implementation:

function adjustHeight():
el.style.height = "auto"
el.style.height = scrollHeight + "px"

This approach assumes the element is visible when measurement occurs.

However, when an ancestor element has display: none, the browser layout engine does not compute dimensions for the element. In this situation:

scrollHeight = 0
offsetHeight = 0
clientHeight = 0
getBoundingClientRect() = 0

If autosize runs while the component is hidden, the algorithm produces:

style="height: 0px"

Because the component remains mounted (for example when hidden using v-show), no lifecycle event is triggered when the element becomes visible again. The incorrect height therefore persists.

Example Scenario

Common UI patterns that trigger the issue include:

• Tab panels implemented with v-show
• Collapsible inspector panels
• Hidden drawers
• Conditional layout containers
• Editor sidebars

Sequence:

1. A textarea with autosize is mounted.
2. Its parent container becomes hidden via display: none.
3. A model update triggers the autosize watcher.
4. scrollHeight is measured while hidden and returns 0.
5. The component writes height: 0px.
6. The container becomes visible again.
7. The textarea remains collapsed.

Root Cause

The autosize algorithm performs layout measurement without verifying that the element is currently visible in the layout tree.

The DOM does not provide valid measurement values for elements inside display: none containers.

Proposed Solution

Add a visibility guard to the autosize routine to prevent measurement when the element is not participating in layout.

The guard uses the DOM invariant:

offsetParent === null

This condition reliably indicates that the element is either hidden via display: none or detached from the layout tree.

If this condition is detected, the autosize routine aborts without writing a height value.

Proposed Implementation

Location
lib-ui/src/inputs/textboxes/Base.vue

Updated adjustHeight logic:

function adjustHeight():
const el = textareaRef.value
if (!el) return

```
if el.offsetParent === null:
    return

el.style.height = "auto"

const height = el.scrollHeight
if height === 0:
    return

el.style.height = height + "px"
```

Behavior After Change

If the textarea is hidden:

• autosize measurement is skipped
• no invalid height is written

When the element becomes visible again, the next valid trigger (input event or value change) performs a correct measurement.

Benefits

Prevents collapsed textareas caused by hidden measurements.

Improves compatibility with common UI patterns including:

• Vue v-show tab systems
• accordion layouts
• inspector panels
• editor sidebars
• dynamic layout containers

Maintains current autosize behavior for all visible elements.

Risk Assessment

Risk level: Very low

The change only affects the autosize routine and only modifies behavior when the element is not visible in the layout tree.

Existing visible behavior is unchanged.

Backward Compatibility

Fully backward compatible.

No API changes.
No prop changes.
No behavior changes for visible components.

Versioning Justification

The change fixes an incorrect edge case in layout measurement without introducing new features or breaking changes.

Version bump: 2.4.1 → 2.4.2

This qualifies as a patch release under semantic versioning.

Future Considerations

If future requirements include fully automatic recovery when visibility changes, a ResizeObserver or visibility-based recalculation mechanism could be introduced.

However, such solutions introduce additional complexity and runtime cost and are not necessary for this stabilization fix.

Conclusion

Adding a layout visibility guard to the autosize measurement prevents invalid height calculations when the textarea is hidden. The change improves robustness across common UI layout patterns while keeping the implementation minimal and safe for a patch release.
