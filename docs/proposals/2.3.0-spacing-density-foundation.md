# Enhancement Proposal — 2.3.0

**Title:** Spacing & Density Foundation Documentation Page
**Status:** Accepted — Implemented in 2.3.0
**Target Version:** 2.3.0 (Minor)
**Date:** 2026-03

---

# 1. Executive Summary

This proposal introduces a dedicated **Spacing & Density foundation page** in the playground to formally document and visually demonstrate:

* The spacing token scale (`--space-*`)
* The density multiplier system (`data-density="compact"`)
* The proportional scaling contract
* Token usage patterns for contributors

This is a documentation and governance enhancement only.

No component behavior changes.
No token renaming.
No breaking API changes.

---

# 2. Background

Version 2.2.0 introduced:

* Density token layer
* `data-density="compact"` scaling
* System-wide adoption across ~46 components
* Semantic Badge variants
* FormField display mode

While the density system is fully implemented, the playground does not yet provide a canonical, centralized visual reference for:

* The spacing scale hierarchy
* Density multiplier behavior
* Contributor token usage patterns

Currently density examples are scattered across component pages.

This creates a governance gap.

---

# 3. Problem Statement

Without a foundation-level documentation page:

* Contributors lack a visual contract for spacing scale
* Density behavior must be inferred from component demos
* Regression detection becomes harder
* Design intent is not formally codified in playground

The density system is systemic and deserves a systemic reference page.

---

# 4. Proposal

Add a new playground page:

`/dev/ui/foundation/spacing-density`

Registered under:

Foundation → Spacing & Density

This page becomes the authoritative visual contract for spacing and density behavior.

---

# 5. Page Structure

## Section 1 — Spacing Scale

Visual grid demonstrating:

| Token | CSS Variable | Default Size |
| ----- | ------------ | ------------ |
| XS    | `--space-xs` | 4px          |
| SM    | `--space-sm` | 8px          |
| MD    | `--space-md` | 12px         |
| LG    | `--space-lg` | 16px         |
| XL    | `--space-xl` | 20px         |

Each rendered as blocks with actual applied padding/margin.

Purpose:

* Make scale hierarchy visible
* Provide regression baseline

---

## Section 2 — Density Scaling

Side-by-side comparison:

Default density
Compact density (`data-density="compact"`)

Demonstrate:

* Padding scaling
* Gap scaling
* Composite layout scaling

Must show proportional relationship is preserved.

---

## Section 3 — Component Propagation Example

Single composite example including:

* ButtonBase
* TextboxBase
* BadgeBase
* FormField

Rendered in:

* Default density
* Compact density

Purpose:

* Demonstrate systemic propagation
* Confirm no hardcoded spacing values remain

---

# 6. Non-Goals

This proposal does NOT:

* Introduce new tokens
* Modify spacing scale values
* Change density multiplier
* Add new density modes
* Introduce per-component density overrides
* Modify component APIs

This is documentation + governance only.

---

# 7. Doctrine Compliance

## Token Doctrine (§4)

The doctrine explicitly encourages extending tokens when needed and forbids hardcoded values.

This proposal strengthens token governance by:

* Making token hierarchy explicit
* Providing visual verification layer

No token changes required.

## Layer Architecture (§2)

The new page:

* Belongs to playground only
* Does not introduce domain logic
* Does not alter Foundation components

Fully compliant.
